# データパイプライン詳細解説：生データからテンソル変換まで

## 1. 概要とスコープ

本ドキュメントでは、推薦モデルのベースとなる「生データの生成」から、モデルの埋め込み（Embedding）層に渡される「テンソル（数値の配列）」へと変換されるまでの一連の**データパイプライン**について、具体例を交えてステップバイステップで詳細に解説いたしますわ。

なお、モデルアーキテクチャ（Two-Tower構造）や `train_step` 内でのバッチ内負例サンプリング（In-batch Negative Sampling）、損失関数の計算といった「モデル学習部分」に関する数理的・具体的なメカニズムにつきましては、別ドキュメントである [train_step_explanation.md](./train_step_explanation.md) をご参照くださいませ。本ドキュメントのゴールは、**学習ロジックに突入するまでに、データがどのような姿（shape）に変換されていくのかを透明化すること**にありますの。

---

## 2. データパイプラインの全体像

現状のシステムにおけるデータパイプラインは、大きく以下の 4 つのフェーズに分かれておりますわ。文字列だったデータが、最終的にニューラルネットワークで処理可能な「整数の行列」に変換されるまでの道のりです。

1. **生データ生成（Data Generation）** : CSVファイルの出力
2. **データの結合（Data Merging）** : pandas DataFrame上での非正規化
3. **データセット化（Dataset Construction）** : `tf.data.Dataset` への抽出
4. **ボキャブラリ（語彙）の獲得と前処理レイヤーの構築** : 整数化への準備

以下に、それぞれのフェーズで何が起きているかを図解と文章で説明いたします。

```text
[データの流れ]

 (1. 生データ生成)
  companies.csv ────┐
  needs.csv    ─────┤
  interactions.csv ─┼─▶ (2. 結合) 
                    │    interactionsをベースに
                    │    Source(企業)とTarget(ニーズ)をJoin
                    ▼
               train_df (pandas DataFrame)
                    │
                    ▼
               (3. データセット化)
               必要な特徴量のみを抽出し
               tf.data.Dataset へ変換
                    │
                    ▼
          interaction_ds (TensorFlow Dataset)
                    │
                    │ 
                    ▼ (4. バッチ化 & 前処理変換)
                StringLookup / TextVectorization によって
                バッチ単位で文字列が整数のテンソルへ変換される
                    │
                    ▼
     ==================================
       Embedding層へ（ここから先はモデルの `train_step` 実体）
       ※対照学習の詳細は `train_step_explanation.md` へ
     ==================================
```

## 3. 各フェーズの詳細

### 3.1. 生データ生成（`generate_sample_data.py`）

モックアップとして、推薦のベースとなる 3 種類の生データを生成・ファイル出力（`data/raw/`）しています。

- **企業データ (`companies.csv`)**:
  - 各企業のマスターデータですわ。「業種大分類・中分類・小分類」「強み」「課題」といった特徴量（フィーチャー）を持ちます。
  - **具体例**:
    - `company_id`: `"c001"`
    - `company_name`: `"サンプル企業1株式会社"`
    - `industry_l`: `"情報通信業"`
    - `description`: `"クラウド開発に強み"`
- **ニーズデータ (`needs.csv`)**:
  - 各企業が発信している「パートナー開拓」「システム刷新」などの要望や募集のマスターデータです。「Target」として推薦される対象となります。
  - **具体例**:
    - `needs_id`: `"n001"`
    - `target_company_id`: `"c042"` (このニーズを発信した企業)
    - `needs_title`: `"AI教育支援"`
    - `needs_detail`: `"研修提供希望"`
- **インタラクションデータ (`interactions.csv`)**:
  - ユーザー行動ログ（ユーザ＝Source企業）です。ある企業（Source）が、別の企業が発信したニーズ（Target）に対して起こした行動（閲覧: view、打診: request、承諾: accept、成約: close）と、その重み（weight）を記録しています。これが推薦モデルにおける学習の**正例**のベースとなりますわ。
  - **具体例**:
    - `source_company_id`: `"c001"` (アクションを起こした企業)
    - `target_needs_id`: `"n001"` (対象のニーズ)
    - `event_type`: `"request"` (打診)
    - `weight`: `5`

### 3.2. データの結合（`training.py:10-19`）

バラバラのCSVデータを読み込み、学習に向けて 1 つのテーブルに非正規化（結合）します。

- 主軸（ファクトテーブル）を `interactions_df` とします。
- **Source側の特徴量付与**: `source_company_id` をキーにして `companies_df` を Left Join します。
- **Target側の特徴量付与**: `target_needs_id` をキーにして `needs_df` を Left Join します。

これにより、「誰が（Source属性）」「どのニーズに（Target属性）」アクションを起こしたのかを 1 行で表現する `train_df` が完成しますの。

**【結合後のデータ (train_df) の具体例】**

先ほどの3つのダミーデータの例が `interactions_df` を主軸として結合されると、以下のような1行のレコードになりますわ。

- `source_company_id`: `"c001"`
- `target_needs_id`: `"n001"`
- `event_type`: `"request"`
- `weight`: `5`
- `company_name`: `"サンプル企業1株式会社"` *(Source企業の属性が結合された)*
- `industry_l`: `"情報通信業"` *(Source企業の属性が結合された)*
- `target_company_id`: `"c042"` *(Targetニーズの属性が結合された)*
- `needs_title`: `"AI教育支援"` *(Targetニーズの属性が結合された)*
- `needs_detail`: `"研修提供希望"` *(Targetニーズの属性が結合された)*

### 3.3. データセット化（`training.py:21-29`）

結合した巨大な DataFrame から、モデルの入力として実際に使われる特徴量だけを抽出し、TensorFlow の DatasetAPI (`tf.data.Dataset`) に変換いたします。

現在抽出している主な特徴量は以下の通りですわ（今後の拡張性を考慮し、辞書型で定義されています）：
- `source_id`: Source企業のID
- `target_id`: TargetニーズのID
- `industry_l`: Source企業の業種（大分類）
- `needs_title`: Targetニーズのタイトル（テキスト）

これにより、バッチ処理やシャッフルなどのデータパイプライン処理を高速に行う準備が整いますわ。

**【tf.data.Dataset 内の 1 サンプルの具体例】**

先ほどの結合データから、必要な特徴量だけが抽出された辞書（Dictionary）形式になりますの。

```json
{
    "source_id": "c001",
    "target_id": "n001",
    "industry_l": "情報通信業",
    "needs_title": "AI教育支援"
}
```

### 3.4. ボキャブラリ・前処理レイヤーの構築（`training.py:31-42`）

モデル内部の Embedding（埋め込み）層は、文字列を直接扱うことができません。代わりに「**0から始まる連番の整数インデックス**」を受け取って、対応するベクトルを引き出します。文字列をこのインデックスに変換するための対応表（辞書）を作る作業が、「語彙（ボキャブラリ）の獲得」ですわ。

- **IDのカテゴリカル・インデックス化（`StringLookup`）**:
  - `company_id` や `needs_id` のユニークな文字列表現を、一意の整数インデックスに変換するための対応表を構築します。
  - **ボキャブラリのイメージ**: モデルはデータ全体をスキャンし、以下のような変換テーブルを作成して保持します。
    | 元の文字列 (String) | ボキャブラリID (Integer) |
    | :--- | :--- |
    | `"[UNK]"` (未知語用) | `0` |
    | `"c001"` | `1` |
    | `"c002"` | `2` |
    | ... | ... |
    | `"c042"` | `42` |
  - **具体例**: データ内に `"c001"` が来たら、このテーブルを参照して `1` という整数に変え、モデル（の Embedding 層の 1 番目のベクトル）に渡す準備が整いますわ。

- **テキストのベクトル化（`TextVectorization`）**:
  - `needs_title` のような自然言語テキストを処理するため、事前に全テキストを読み込ませて（`.adapt()`）、単語レベルでのボキャブラリ（トークンごとの対応表）を作ります。
  - **ボキャブラリのイメージ**: 出現頻度順などに単語が並べられ、それぞれにIDが振られます。
    | 単語トークン | ボキャブラリID |
    | :--- | :--- |
    | `""` (パディング用) | `0` |
    | `"[UNK]"` (未知語用) | `1` |
    | `"支援"` | `2` |
    | `"AI"` | `3` |
    | `"教育"` | `4` |
  - **具体例**: `"AI教育支援"` というテキストが入力された場合、まず `["AI", "教育", "支援"]` のように分割（トークナイズ）されます。その後ボキャブラリ表を参照し、`[3, 4, 2]` のような整数の配列に変換されますの。

## 4. 最終フェーズ：学習モデルへの引き継ぎとテンソル変換

データパイプラインによって構築された `interaction_ds` と、準備された各種前処理レイヤー（`StringLookup` など）は、`MatchingModel` に引き渡されます。これまでに準備したデータが、実際のテンソルとしてどのように「実体化」するのかを見てみましょう。

### 4.1. バッチ化による「行から列へ」の構造変換

データセットは `interaction_ds.batch(128)` のようにバッチサイズ（例: 128件）単位にまとめられます。
この時、モデルの `train_step(self, data)` に引数 `data` として入ってくる段階では、データの持ち方が「**1件ずつの辞書の集まり**」から「**特徴量ごとの配列（列）をまとめた辞書**」へと構造が変換されます。

**【変換のイメージ】**

```text
[バッチ化前 (行指向: 1件ずつ)]
1件目: {"source_id": "c001", "target_id": "n001"}
2件目: {"source_id": "c042", "target_id": "n099"}
3件目: {"source_id": "c015", "target_id": "n031"}

       ↓ (batch変換)

[バッチ化後 (列指向: 特徴量ごとに配列化)]
{
  "source_id": ["c001", "c042", "c015"],
  "target_id": ["n001", "n099", "n031"]
}
```

**【学習に渡される直前のデータ (バッチ) の具体例】**

これまでの例（`c001`）に加え、他に2件のデータが抽出されたと仮定し、バッチサイズが `3` の場合、以下のような TensorFlow のテンソル（行列）の辞書として渡されますわ。

```json
{
    "source_id": tf.Tensor([b"c001", b"c042", b"c015"], shape=(3,), dtype=string),
    "target_id": tf.Tensor([b"n001", b"n099", b"n031"], shape=(3,), dtype=string),
    "industry_l": tf.Tensor([b"情報通信業", b"製造業", b"サービス業"], shape=(3,), dtype=string),
    "needs_title": tf.Tensor([b"AI教育支援", b"自動化の相談", b"新規事業開発"], shape=(3,), dtype=string)
}
```

各キー（特徴量）に対して、「バッチサイズ分のデータが入った1次元配列（ベクトル）」がまとまって渡されているのが分かるかと思いますの。このテンソルが、それぞれモデル内の `StringLookup` や `TextVectorization` に入力され、先述のボキャブラリ変換が行われていきます。

### 4.2. ボキャブラリによる「文字から整数」への変換

モデルの内部（各Tower）にて前処理レイヤーに通されると、文字列の配列が「整数の配列」に変換され、モデルの真の顔である Embedding 層が処理できる形へとなりますわ！

- `StringLookup` を通過した `source_id`:
  ```python
  tf.Tensor([ 1, 42, 15], shape=(3,), dtype=int64)
  ```
  *(文字列から、単純な整数IDへ1対1に変換されますの)*

- `TextVectorization` を通過した `needs_title`:
  ```python
  tf.Tensor(
  [[ 3  4  2  0]   # 「AI」「教育」「支援」 (3トークン)
   [12 18  5 20]   # 「自動」「化」「の」「相談」 (4トークン) -> バッチ内最長
   [24 16 19  0]], # 「新規」「事業」「開発」 (3トークン)
   shape=(3, 4), dtype=int64)
  ```
  *(単語がすべて整数IDに変換されます！ バッチ内の最長テキスト（4トークン）に合わせて配列の長さが揃えられ、単語数が足りない部分は `0` (パディング) で埋められて綺麗な2次元行列になるのがミソですわ)*

この「整数の配列たち」が最終的に Embedding 空間（例えば32次元のベクトル空間）へ写像され、スコア行列の計算へと進んでいくのです。

### 4.3. 「B個のペアのテンソル」としての抽出（Two-Towerへの入力）

`train_step_explanation.md` にて「入力バッチ ($B$ 個のペアのテンソル)」として図解されているのは、まさにこの辞書の中から抽出される**実体**を指しておりますの。

`train_step(self, data)` に渡された上記の辞書型バッチから、モデルは「Source側」と「Target側」に用いる特徴量テンソルを見つけ出し、2つのタワー（Tower）にそれぞれ分配（ペアとして抽出）いたします。

**【抽出のイメージ（$B=3$ の場合）】**

```python
# train_step内での引数 data から、必要な特徴量をテンソルとして抽出
source_features = data["source_id"]
target_features = data["target_id"]
```

これを前処理レイヤーに通した結果のイメージで捉え直すと、最終的に以下の **2つのテンソルのペア** が手に入り、実際のニューラルネットワーク（Embedding層）に渡されますわ。

1. **Source側のテンソル (shape: 3)**: `tf.Tensor([ 1, 42, 15], dtype=int64)`
   *(※ `source_id` から変換済み)*
2. **Target側のテンソル (shape: 3)**: `tf.Tensor([ 2, 99, 31], dtype=int64)`
   *(※ `target_id` の `[n001, n099, n031]` が、それぞれ `[2, 99, 31]` のボキャブラリIDへ変換されたと仮定)*

ここが**データパイプラインの終着点**であり、同時に**学習ロジック（Two-Towerモデル）の出発点**となります。

上記の「バッチサイズ $B$ 分のペアのテンソル」が、Source Tower と Target Tower にそれぞれ入力されることで、いよいよ推薦のための対照学習（In-batch Negative Sampling）が始まりますの！

### 4.4. 発展：その他の特徴量（`needs_title`, `industry_l` 等）はどうなるのか？

お気付きになられましたでしょうか。データセット化のフェーズで抽出され、`TextVectorization` まで準備されていた `needs_title` や `industry_l` は、**現在の `MatchingModel`（`training.py` 実装）の基本形では、あえて推論・学習のテンソルとして抽出・使用されておりません**。

現在の Two-Tower モデルは、複雑さを避けるために最もミニマムな「ID同士の協調フィルタリング（企業ID $\times$ ニーズID）」として実装されているからです。

**【もしこれらをモデルで使う場合（特徴量の追加）】**

これらの特徴量をモデルに組み込む（コンテンツベースの推薦を混ぜる）場合は、モデルの内部で**「別々にベクトル化してから、後で合体させる」**というアプローチをとりますの。

**【特徴量合体のステップ】**

1. **特徴量の抽出**:
   辞書型のバッチから「ID」のほか、「ニーズタイトル（テキスト）」「業種（カテゴリカル）」「企業年齢（単一の数値）」など、使いたい部品をそれぞれ独立して取り出します。
2. **個別のベクトル化**:
   - **ID（固有の識別子）**: そのまま専用の Embedding 層を通し、例えば 32 次元のベクトルに変換します。
   - **テキスト（文章など）**: `TextVectorization` で単語の ID 列に変換し、単語ごとのベクトルを出した後、文章全体の意味として平均化（またはプーリング）し、同じく 32 次元のベクトルに変換します。
   - **カテゴリカル特徴量（業種、地域など）**: IDと同様に、`StringLookup` などで整数インデックスに変換後、専用の Embedding 層を通して小さな次元（例: 4〜8次元程度）のベクトルに独立して変換します。
   - **数値特徴量（従業員数、売上規模、企業年齢など）**: 正規化（例えば min-max スケーリングなど）を行ったスカラー値として、そのまま1次元ベクトルとして扱うか、前処理として小さな `Dense` 層を通して特徴抽出を行います。
3. **ベクトルの結合（Concat）**:
   出来上がったすべてのベクトル（ID 32次元 + テキスト 32次元 + カテゴリ 8次元 + 数値 1次元など）を横に並べて接着（コンカチネート）します。これにより、IDの持つ「過去の行動履歴」と、内容や属性の持つ「類似性」を多角的に併せ持つ、より強力な特徴表現になりますわ！

**【最終的な抽出物（ペアのテンソル）の具体例】**

この拡張を行った場合、最終的に Two-Tower が内積（対照学習）を行う $B=3$ のペアのテンソルは、次元数が膨らんだ以下のようになりますわ！

1. **Source側（企業）の結合テンソル (shape: 3, 41)**:
   企業ID（c001など）の 32 次元ベクトルに、業種（「情報通信業」など）の 8 次元ベクトルと、企業年齢（「設立10年」など）の 1 次元の数値を結合した 41 次元ベクトルです。
   ```python
   tf.Tensor([
     # ↓ IDの32次元分 ↓     ↓ 業種の8次元分 ↓  ↓ 企業年齢 ↓
     [0.9, 0.1, ..., 0.3,   0.2, ..., 0.6,   10.0], # <- c001 の情報
     [0.2, 0.8, ..., 0.1,   0.7, ..., 0.1,    5.5], # <- c042 の情報
     [0.5, 0.5, ..., 0.7,   0.3, ..., 0.4,   25.0]  # <- c015 の情報
   ], shape=(3, 41), dtype=float32)
   ```

2. **Target側（ニーズ）の結合テンソル (shape: 3, 64)**:
   ニーズIDの 32 次元ベクトルと、タイトル（「AI教育支援」など）の 32 次元ベクトルがガッチャンコ（連結）された 64 次元ベクトルです。
   ```python
   tf.Tensor([
     # ↓ ID(n001)の32次元分 ↓     ↓ タイトル("AI教育支援")の平均32次元分 ↓
     [0.8, 0.2, ..., 0.4,       0.1, 0.9, ..., 0.5], 
     [0.3, 0.7, ..., 0.2,       0.4, 0.1, ..., 0.8], 
     [0.4, 0.6, ..., 0.6,       0.7, 0.3, ..., 0.2]  
   ], shape=(3, 64), dtype=float32)
   ```

> ※ 注意：内積を計算するためには最終的に両タワーの出力次元数（上記の例では32次元と64次元）を揃える必要があります。そのため、実際のモデル実装では `Dense` 層などを追加して次元を圧縮・マッピングするプロセスが入りますの。

前処理レイヤー（ボキャブラリなど）までは既に**データパイプラインのフェーズ4までで完成**しておりますので、モデルのネットワーク構造を少し書き換えるだけで、即座にこれらを「ペアのテンソルの一部」として活用できるようになっていますわ！
